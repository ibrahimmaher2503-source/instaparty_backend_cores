# Implementation Plan: Discovery — Meilisearch Search & Wishlists

**Branch**: `004-discovery-meilisearch` | **Date**: 2026-04-30 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/004-discovery-meilisearch/spec.md`

---

## Summary

Add Meilisearch-backed full-text search on the `services` table with bilingual (EN/AR) fields, filterable `product_type` and occasion facets, and paginated results for the customer API. Implement wishlists (add/remove, lazy creation). Migrations for `wishlists`, `wishlist_items`, `saved_searches`, `search_logs`. Admin re-index action in Filament.

Depends on: Catalog module (Phase 2.0) — `services`, categories, occasions must exist and be published.

---

## Technical Context

**Language/Version**: PHP 8.3, Laravel 12
**Primary Dependencies**: `laravel/scout` + `meilisearch/meilisearch-php` driver, `spatie/laravel-permission`, `spatie/laravel-translatable`
**Storage**: MySQL 8 (Discovery tables) + Meilisearch (search index)
**Testing**: Pest — Feature tests with Meilisearch running in Docker; unit tests for `toSearchableArray()` output
**Target Platform**: Linux (Docker Compose) — Meilisearch as a sidecar service
**Project Type**: Modular monolith API + Filament admin
**Performance Goals**: Search results in under 1 second p95; index updates async via Scout queue
**Constraints**: `SCOUT_QUEUE=true` (async indexing); Arabic tokenization via Meilisearch built-in Unicode support; zero-downtime re-index via Meilisearch index swap; no `service_search_index` MySQL table (locked decision)
**Scale/Scope**: Phase 3.0 — customer search and wishlists; saved search UI deferred to Phase 1.5

## Complexity Tracking

No constitution violations.

| Decision | Why Needed |
|---|---|
| `Searchable` trait added to `Service` in Catalog module | Scout requires it on the indexed model; the indexing logic (`toSearchableArray`) belongs to Catalog but is triggered by Discovery |
| `occasion_ids` flattened at index time | Meilisearch can only filter on arrays at the top-level document level; M2M must be flattened in `toSearchableArray()` |
| Zero-downtime re-index via index swap | Meilisearch supports `swapIndexes` — create `services_temp`, import all, swap atomically with `services`, drop temp |

## Implementation Order (Day by Day)

### Day 1 — Meilisearch + Indexer

1. Write 4 migrations
2. Configure Scout in `config/scout.php` + `.env` (Meilisearch URL, key, `SCOUT_QUEUE=true`)
3. Add `Searchable` trait to `Service` model; implement `toSearchableArray()` (flattens JSON name/description to `name_en`, `name_ar` etc.; eager-loads occasions for `occasion_ids`)
4. Register Meilisearch index settings in `DiscoveryServiceProvider::boot()` (searchable, filterable, sortable attributes, Arabic tokenizer)
5. Write Discovery module models (`Wishlist`, `WishlistItem`, `SavedSearch`, `SearchLog`)
6. Write `DiscoveryServiceProvider`
7. Implement `ReindexServicesAction` (Filament action using `Service::makeAllSearchable()` with index swap)

### Day 2 — API + Tests

1. `SearchServicesAction` — calls `Service::search($query)->where(...)` and maps to DTO
2. `AddToWishlistAction` — lazy-creates wishlist via `firstOrCreate`, inserts `WishlistItem` (idempotent via UNIQUE constraint)
3. `RemoveFromWishlistAction` — deletes `WishlistItem`
4. HTTP layer: controllers, requests, resources with locale resolution
5. Pest tests: search in Arabic returns results, type filter narrows correctly, wishlist add/remove
